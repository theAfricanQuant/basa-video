From presentation renderer to course engine

Pi directs.
Basa delivers.

Let an agent turn a book, notebook, PDF, transcript or prompt into a reviewed course. Keep the part that must never improvise—voice, timing, captions and MP4 rendering—inside Basa.

Shipped todayQMD or Reveal.js HTML with speaker notes becomes a synchronized narrated MP4.
Proposed layerSource material becomes a plan, approved lessons and course artifacts before Basa renders them.

01 / The decision

Make Basa a source-to-course compiler.

Do not replace the renderer with an agent. Put a bounded course-authoring agent above it.

Pi’s SDK is designed for embedded agent sessions, custom interfaces and automated workflows, with event streaming and configurable resources.[1] That makes it a plausible control plane—not a new media engine.

The user gives Basa knowledge. Pi proposes how to teach it. The teacher approves it. Basa turns the approved lesson into dependable media.

03 / Architecture

QMD survives—quietly.

QMD can remain the first internal lesson target even when the teacher never writes it. The durable boundary is the manifest, not the authoring file.

04 / Responsibility

Agency belongs at the top. Determinism belongs at the bottom.

Current renderer preserved

Pi decides what to propose

  • Structurecourse arc, lesson order, objectives and assessments
  • Pedagogyexamples, explanations, pacing and slide/narration balance
  • Groundingfind the source passage behind each factual claim
  • Revisionrespond to teacher feedback and regenerate one lesson

Basa decides what can ship

  • Contractschema, approved narration and stable artifact identities
  • Mediavoice synthesis, measured timing, screenshots and captions
  • Policyvoice consent, provider rules, rights and provenance
  • Outputrepeatable MP4, subtitles, manifests and course package

08 / Inputs

Each source needs its own truth-preserving adapter.

“Supports PDF” should mean more than extracting a wall of text. Each adapter must retain the source locations a teacher can inspect.

InputPreserveCourse opportunityPrimary risk
Transcriptspeaker, timestamps, sectionsfastest clean proof of conceptspoken repetition becoming slide clutter
Book / PDFpage, heading, figures, captionsstructured multi-lesson coursecopyright and weak page extraction
Notebookcell order, code, outputs, errorsexecutable demonstrationsunsafe or non-reproducible execution
Promptbrief, supplied references, decisionscourse from an instructor’s intentunsupported claims if sources are absent

09 / Long works

Retrieve; do not stuff.

A whole book should be chunked into a source map and searched per lesson. Each lesson gets bounded evidence and a fresh session. The full work should not live in AGENTS.md, a skill, or one enormous prompt.

  • stable chunk and page identifiers
  • lesson-specific retrieval budget
  • citations retained through generated notes
  • source hash invalidates affected drafts

10 / Notebooks

Execution is opt-in.

Notebook ingestion may read cells by default. Running code requires an explicit teacher action and a resource-bounded environment managed through uv.

  • network off unless declared
  • project-scoped filesystem
  • time and memory limits
  • captured environment and failures

11 / Trust boundary

Do not let the course author become the machine owner.

Pi’s own documentation warns that packages run with full system access and that skills may cause executable actions.[4]

Pin and review

Ship only first-party skills and extensions. Pin an exact reviewed version; do not dynamically install community packages during a build.

Treat sources as data

A PDF or notebook may contain prompt-injection text. Ingested material cannot grant tools, modify policy or approve its own lesson.

Declare rights

Every source records the user’s rights basis. Voice choice still passes Basa’s existing consent and provider policy.

The local Pi experiment currently has 0.80.2 installed; npm reported 0.84.2 on 22 August 2026.[5] The proof should deliberately pin whichever exact version is reviewed, rather than float to “latest.”

12 / First build

Prove one lesson, not the whole vision.

Smallest useful flow

  1. Give Basa Markdown or a transcript.
  2. Pi proposes three lessons.
  3. The teacher approves the plan.
  4. Pi produces lesson one as QMD + notes.
  5. Existing Basa renders one MP4.

Success means

  1. claims trace to the supplied source
  2. objectives are explicit and testable
  3. slides and narration complement each other
  4. the generated deck passes validation
  5. voice, slide and captions remain synchronized
  6. lesson one can regenerate in isolation

13 / Roadmap placement

Experiment now. Productize later.

This protects the lean path while letting us test the most important new product assumption immediately.

Now / parallel proofTranscript or Markdown → three-lesson plan → teacher approval → one QMD pilot → current Basa MP4.
Milestones 1–2Stabilize releases and introduce the normalized presentation manifest plus PDF/image inputs.
Milestones 3–6Improve timing, voices, media and structured input adapters without weakening the render contract.
Milestone 7Promote the proof into books, PDFs, notebooks, transcripts and prompt-driven courses with durable approvals, provenance and resumable lesson generation.

14 / Recommendation

Build Pi as an optional course-authoring package above Basa.

The strategic leap is real, but the implementation can stay lean: Pi is the director, the manifest is the contract, the teacher owns approval, and Basa is the studio that delivers.
