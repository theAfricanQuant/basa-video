Architecture direction · 22 August 2026

Quarto is a door.
Not the building.

Basa began with a teacher, a Quarto deck and a simple question: can the presentation and its speaker notes become a useful narrated video? The answer now points to something broader—one dependable teaching-video engine with several ways in.

The essential input is not QMD.

It is an ordered set of visuals, reviewed narration and enough structure to build a deterministic timeline.

The question behind Basa

The original use case should remain visible as the product expands. It protects Basa from becoming a generic AI-video application with no clear publishing contract.

“I already have the presentation I use to teach. Why should turning it into a narrated course video require rebuilding the lesson somewhere else?”

ArtBox, Voicebox and similar experiments demonstrated pieces of the idea, but their friction revealed the real opportunity: keep the authored teaching material authoritative and make video generation a repeatable publishing step.

Yes.

Basa can work without QMD. Removing QMD does not remove the need for visuals, narration or ordering—it changes how those inputs arrive.

Where the previous study stopped

The product comparison established Basa’s current differentiation and recommended fragment-level narration next. This study keeps that work and inserts a smaller universal-input seam before the more complex fragment timeline.

Shipped today

QMD and Reveal HTML

  • Standard speaker notes supply narration.
  • One stable visual state is captured per slide.
  • Kokoro is the local default; ElevenLabs is optional.
  • Measured audio drives MP4 and caption timing.
  • Build cache and provenance manifest are written.
Designed, not implemented

Universal presentation manifest

  • PDF or ordered images provide stable visuals.
  • Markdown or YAML supplies reviewed narration.
  • AI may draft narration into an editable file.
  • PPTX and a thin interface arrive through later adapters.
  • Every route converges before synthesis and rendering.

The exact drop point: Basa currently normalizes slides inside the QMD/Reveal render path. It does not yet expose a versioned input manifest or accept PDF, images or PPTX. The next implementation begins by formalizing that boundary—not by building a second renderer.

One core, many doors

Each adapter is responsible only for producing ordered visual states and reviewed narration. Provider selection, timing, captions, caching, provenance and FFmpeg packaging remain shared.

The portable contract

The manifest should be plain, reviewable and source-controlled. It is not a new presentation format; it is the hand-off between an authored visual source and Basa’s existing narration-and-timing engine.

What the manifest owns

A QMD adapter can generate it automatically. A PDF user can create it with basa-video init. A future local interface can edit it without inventing a private database or project format.

Identity
Schema version, source file and stable visual-state identifiers.
Ordering
The exact page, slide or fragment sequence.
Narration
Reviewed text, language, voice and optional pronunciation hints.
Rendering
Output size, pauses, captions and future media-layer settings.
Provenance
Enough source information to explain and reproduce the build.

What using Basa could feel like

Current commands are separated from proposed commands so the design cannot be mistaken for shipped functionality.

Available

Quarto source

Speaker notes are extracted automatically and remain beside the teaching material.

basa-video render course.qmd
Available

Rendered Reveal deck

The original QMD is unnecessary when the HTML already contains embedded aside.notes.

basa-video render course.html
Proposed

Any slide tool via PDF

Export PowerPoint, Keynote, Canva, Google Slides or another presentation as PDF, then review one narration entry per page.

basa-video init course.pdf
basa-video render course.basa.yaml
Proposed

AI-assisted script drafting

Generate an editable narration draft from visible slide text. Rendering remains a separate, explicit action after review.

basa-video narrate course.pdf
--output course.basa.yaml
Later

PowerPoint with notes

Extract notes directly while converting the slide visuals through a stable cross-platform path.

basa-video render course.pptx

AI drafts; teachers approve

Visible slide text can help draft narration, but a confident synthetic voice can make a weak or incorrect explanation sound authoritative. Review must remain part of the file-based workflow.

Separate drafting from rendering

narrate writes an editable manifest. render consumes reviewed narration. One command never silently performs both for new drafts.

Validate before synthesis

Missing narration, page-count mismatches and unsupported inputs fail before remote API cost or local model computation begins.

Keep authorship visible

The manifest records whether narration was supplied, AI-drafted or edited, while the teacher remains responsible for factual and pedagogical approval.

A thin interface, eventually

The interface should expose the same files and commands rather than become a second presentation editor or private project format.

1 · ChooseDrop in a deckQMD, HTML, PDF or a later supported format.
2 · InspectSee ordered visualsThumbnails expose missing pages and unstable captures.
3 · ReviewEdit narrationExisting notes appear; missing notes can be written or drafted.
4 · ListenChoose and preview voiceProvider, accent, language and rights information stay explicit.
5 · RenderRun the same engineProgress, errors and output paths reflect the CLI pipeline.

Where this lands in the roadmap

The manifest begins in the release-quality milestone because it is an architectural boundary. PDF and image workflows follow immediately, before fragment-level timing.

M1

Release + manifest

Cross-platform confidence, public packaging and version 1 of the normalized presentation contract.

M2

PDF + images

init, narration sidecars, AI draft separation and the first universal static-deck workflow.

M3

Timeline fidelity

Reveal fragments, deterministic visual states, forced alignment and optional burned captions.

M4

Voices + languages

Reviewed optional providers, capability metadata and tested German support.

M5

Richer media

Music, embedded video, transitions, chapters and media-layer provenance.

M6

PPTX + interface

Structured adapters and a local interface sharing the exact CLI pipeline.

Basa combines ordered visual scenes with reviewed narration and produces a synchronized, reproducible teaching video.

Quarto remains the best first door. It is source-controlled, expressive and already carries speaker notes. The manifest simply makes sure it is not the only door.
